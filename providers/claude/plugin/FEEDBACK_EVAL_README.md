# feedback-eval experiment branches

This is an exploratory feedback-steering branch (`feedback-eval/skills`) for a
Claude Code agent-eval experiment. It is not a production change to the
`stripe` plugin's behavior — it exists to test whether small nudges toward
`stripe feedback` change agent behavior in existing eval cases.

## What's on this branch

This is the **shared base** for two sibling hook branches
(`feedback-eval/stop` and `feedback-eval/subagent-stop`). It contains:

1. A soft-steering message appended to the end of a few CLI-invoking skills'
   instruction flow (`stripe-projects`, `stripe-docs`, `stripe-directory`),
   asking the agent to consider calling `stripe feedback` once it has
   finished using the skill.
2. Shared, **dormant** hook-support scripts under `hooks/` — helpers the two
   sibling branches use to build their Stop / SubagentStop hooks. Nothing on
   this branch registers a hook. There is no `hooks/hooks.json` here, and
   these scripts are never invoked automatically.

## Do not hand-edit generated skill copies

`providers/claude/plugin/skills/**` (and the sibling `providers/*/plugin/skills/**`
and top-level `skills/**` directories) are generated by `scripts/sync.js` from
[docs.stripe.com/.well-known/skills](https://docs.stripe.com/.well-known/skills)
and are overwritten on every sync. **Never hand-edit files under those
directories.**

The soft-steering message is instead injected by `scripts/sync.js` itself,
scoped to only the Claude-provider output directory and only the three
selected skills (see `applyFeedbackSteering` in that script). Because the
change lives in the generator, it survives future `node scripts/sync.js`
runs; the generated `SKILL.md` files were produced by running the (modified)
sync script, not edited by hand. Every other provider and the top-level
`skills/` directory continue to receive the untouched upstream content.

## What the sibling branches add

- `feedback-eval/stop`: registers a plugin `Stop` hook that inspects the
  *parent* session's transcript and, when it looks eligible, asks the parent
  agent (once) to consider running `stripe feedback`.
- `feedback-eval/subagent-stop`: registers a plugin `SubagentStop` hook that
  inspects the *subagent's own* transcript (`agent_transcript_path`) and,
  when eligible, asks that subagent (once) to consider running
  `stripe feedback`.

Both are independent branches based on this one; neither contains the
other's hook commits. Both hooks are observation-first: they always append a
structured record to a run-local `.stripe-feedback-eval/events.jsonl`
journal (via `hooks/feedback-observation.sh`), whether or not the session
was eligible, and they never call `stripe feedback` themselves — only the
agent (parent or subagent) can decide to do that.

## Out of scope here

An external eval-runner session (in `/pay/src/pay-server`, not this repo)
configures and runs the released `@stripe/cli@latest` and QA feedback
routing, and executes the actual eval cases against these plugin worktrees.
Nothing in this repo installs a CLI, configures routing, or triggers an eval
run.
